# Localisation and internationalisation standard — template

> **Template.** Copied to `{FLUTTER_STANDARDS_ROOT}/YYYYMMDD-L10N_STANDARD.md` with locales filled from foundation doc 02 §4.

**Rule of thumb:** internationalisation is cheap when built in and expensive when retrofitted. Even a single-locale app should externalise its strings — the cost is one indirection, and it buys copy review, consistency, and the option to expand.

---

## 1. Scope

| Item | Value |
|------|-------|
| Locales at launch | `REPLACE:LAUNCH_LOCALES` |
| Planned locales | `REPLACE:PLANNED_LOCALES` |
| Fallback locale | `REPLACE:FALLBACK_LOCALE` |
| RTL required | `REPLACE:RTL_REQUIRED` |
| Mechanism | `REPLACE:L10N_MECHANISM` (default: ARB + `flutter_localizations` + `gen_l10n`) |

---

## 2. Strings

- **No user-visible string literal in a widget.** Every one comes from the generated localisations. This includes error messages, empty-state copy, button labels, and — the ones always forgotten — semantic labels, tooltips, and accessibility announcements.
- Keys are semantic and describe purpose, not content: `checkoutSubmitButton`, not `submit` or `buyNow`. Content changes; purpose does not.
- Every key carries a **description** for translators, plus placeholder types and examples. A translator seeing `{count} items` with no context cannot know whether `count` is a quantity of products or a number of days.
- **Never concatenate translated fragments.** Word order differs between languages; a sentence assembled from three strings is untranslatable. Use one string with placeholders.
- Plurals use ICU plural syntax — not `if (n == 1)`. Languages have between one and six plural forms; a binary branch is wrong in most of them.
- Gender and select cases use ICU `select`.
- The default locale's ARB is the source of truth; missing keys in other locales fall back and are reported.

---

## 3. Formatting

Never hand-format anything locale-dependent.

| Data | Rule |
|------|------|
| Dates and times | `intl` `DateFormat` with the locale; never `'${d.day}/${d.month}'` |
| Numbers | `NumberFormat` — decimal and grouping separators differ by locale |
| Currency | `NumberFormat.currency` with an explicit currency code; symbol placement is locale-dependent |
| Percentages, compact numbers | `NumberFormat` |
| Relative time | A locale-aware formatter, with plural rules |
| Lists | Locale-aware list formatting, not `join(', ')` |
| Sorting | Locale-aware collation, not code-unit ordering |
| Time zones | Store UTC, display in the user's zone, and state which zone when it matters |

---

## 4. Layout

- **Never assume text length.** German runs 30–40% longer than English; Japanese much shorter. Layouts that fit English exactly break elsewhere.
- Text wraps rather than truncating, unless truncation is a deliberate, specified choice.
- Fixed-width containers sized to a translated string are a defect.
- **Directional properties, not physical ones**: `EdgeInsetsDirectional`, `AlignmentDirectional`, `start`/`end`. `left`/`right` in a layout is an RTL bug.
- Icons that indicate direction (back, forward, next) mirror in RTL; icons that do not (play, checkmark, logos) must not.
- Test at the longest expected translation, not the shortest.

---

## 5. RTL

When `REPLACE:RTL_REQUIRED` is yes:

- Every screen is verified in an RTL locale, not just the ones with obvious layout.
- Mixed-direction text (an Arabic sentence containing a Latin brand name) renders correctly.
- Gestures, animations and swipe directions mirror.
- Numbers and dates follow the locale's convention, which is not always mirrored.
- At least one golden test per primary screen in RTL.

---

## 6. Non-text localisation

Images with embedded text are localised or, better, not created — text belongs in a text widget over an image, not baked into pixels. Also locale-dependent: currency, units of measure, address and phone formats, name order, first day of the week, calendar systems, legal copy, and support contact details.

---

## 7. Process

1. A new string is added to the source ARB with a description before it is used.
2. Code generation runs; the generated accessor is used.
3. Missing translations are reported in CI and fall back visibly in non-production builds so gaps are seen rather than silently masked.
4. Translations arrive through `REPLACE:TRANSLATION_PROCESS`.
5. Pseudo-localisation (`REPLACE:PSEUDOLOC`) is used in development to surface hardcoded strings and length problems before translators are involved — it finds in minutes what review finds in weeks.

---

## 8. Testing

- A lint or grep check fails the build on user-visible string literals outside `core/l10n/`.
- CI reports keys missing from any target locale.
- Widget tests run in at least the default locale plus one long-text locale plus, where required, one RTL locale.
- Golden tests cover RTL and long-text variants of primary screens.
- Formatter usage is unit-tested against multiple locales — including one that uses `,` as a decimal separator, which is where naive parsing breaks.

---

## 9. Anti-patterns

- Hardcoded user-visible strings, especially in error paths and semantic labels.
- Concatenating translated fragments.
- `if (count == 1)` instead of ICU plurals.
- Keys named after their English content.
- Keys with no description for the translator.
- `left`/`right` padding and alignment.
- Fixed widths sized to English.
- Manual date or number formatting.
- Text baked into images.
- Adding a locale without testing layout in it.
